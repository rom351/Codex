# Часовая лавка — интернет-магазин часов

Готовый магазин на Node.js: каталог с фильтрами и поиском, карточки товаров, корзина, оформление заказа,
контактная форма и заказ звонка, админ-панель (заказы, заявки, товары, загрузка фото). Без внешних сервисов: данные лежат в одном файле SQLite.

## Запуск на своём компьютере

Нужен Node.js 20 или новее.

```bash
cd watch-shop
npm install
npm start
```

Откройте <http://localhost:3000>. Админ-панель: <http://localhost:3000/admin>, пароль по умолчанию `admin`
(только для локального запуска). При первом старте создаётся демо-каталог из 12 часов с вымышленными брендами.

Тесты: `npm test`.

## Настройки

Все настройки задаются переменными окружения; шаблон со всеми параметрами — `.env.example`
(скопируйте его в `.env`). Главное:

| Переменная | Что делает |
|---|---|
| `SHOP_NAME`, `SHOP_SLOGAN` | Название и слоган |
| `SHOP_PHONE` | Телефоны через запятую. В шапке, подвале и на странице «Контакты» становятся ссылками для звонка |
| `SHOP_EMAIL`, `SHOP_ADDRESS`, `SHOP_HOURS` | Почта, адрес и время работы |
| `CURRENCY` | Код валюты, по умолчанию `UAH` (гривна) |
| `TIMEZONE` | Часовой пояс для времени заказов в админке, по умолчанию `Europe/Kyiv` |
| `DELIVERY_COURIER_FEE`, `DELIVERY_POST_FEE`, `FREE_DELIVERY_FROM` | Стоимость доставки и порог бесплатной доставки, в гривнах. Значения по умолчанию примерные — поставьте свои |
| `SESSION_SECRET`, `ADMIN_PASSWORD` | Обязательны в боевом режиме (без них сервер не запустится) |
| `SITE_URL` | Адрес сайта, нужен для `sitemap.xml` и ссылок |

## Заявки (мини-CRM)

На странице «Контакты» есть две формы: «Заказать звонок» (имя и телефон) и «Написать нам» (с сообщением). В шапке
и подвале — ссылка «Заказать звонок». Всё, что отправили посетители, попадает в админ-панель, раздел **Заявки**:
статус (новая, в работе, обработана, спам), заметка менеджера, а в карточке заявки и заказа видны другие обращения
и заказы этого клиента (ищутся по номеру телефона). Новые заявки показываются счётчиком в меню админки.

Вне боевого режима, если контакты не заданы, подставляются демо-номера, демо-почта и демо-адрес; в боевом режиме
(`NODE_ENV=production`) без `SHOP_PHONE` телефонов в шапке не будет.

## Выкладка в интернет (рекомендуемый вариант)

Магазин хранит базу и фото на диске, поэтому ему нужен сервер с постоянным диском. Самый простой вариант —
**обычный VPS (1 ядро, 1–2 ГБ памяти) + Docker**. HTTPS-сертификат для домена получает и продлевает Caddy
автоматически, всё уже описано в `docker-compose.yml`.

1. Купите домен и VPS с Ubuntu. В DNS домена создайте `A`-запись на IP сервера (и для `www`, если нужен).
2. На сервере установите Docker и клонируйте репозиторий.
3. Настройте окружение:
   ```bash
   cd watch-shop
   cp .env.example .env
   nano .env
   ```
   Заполните `DOMAIN` (например `shop.example.com`), `SITE_URL=https://shop.example.com`, `ADMIN_PASSWORD`,
   `SESSION_SECRET` (получить: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`),
   контакты магазина. `PORT` и `DATA_DIR` не меняйте.
4. Запустите: `docker compose up -d --build`.
5. Откройте `https://ваш-домен` и `https://ваш-домен/admin`.

Обновление после изменений в репозитории: `git pull && docker compose up -d --build`.
База и фото хранятся в томе Docker `shop-data` и при обновлении не теряются.

**Резервная копия** (делайте регулярно — в базе заказы):
```bash
docker compose exec shop node scripts/backup.js
docker compose cp shop:/data/backups ./backups
```

Альтернатива без своего сервера — облачные платформы (Fly.io, Railway, Render): подойдёт тот же `Dockerfile`,
но обязательно подключите постоянный том и смонтируйте его в `/data`, иначе заказы и фото пропадут при перезапуске.

> Образ Docker в рамках разработки не собирался (в среде разработки не было Docker-демона). Проверены
> синтаксис `docker-compose.yml`, чистая установка `npm ci --omit=dev`, запуск в боевом режиме и резервная копия.

## Что заполнить перед открытием магазина

- Контакты в `.env` и тексты страниц «Доставка и оплата», «О магазине», «Политика конфиденциальности»
  (`src/views/page-*.ejs`). Они написаны как нейтральный шаблон — приведите их в соответствие с реальными
  условиями и законодательством Украины (персональные данные, возврат, гарантия).
- Блок преимуществ на главной (`src/views/home.ejs`: «Гарантия», «Проверка», «Возврат») и список под кнопкой
  «В корзину» на карточке товара (`src/views/product.ejs`) — оставьте только то, что вы действительно предоставляете.
- Страница «Доставка и оплата» (`src/views/page-delivery.ejs`): названия служб (Новая почта, Укрпочта), условия оплаты,
  блок «Обмен и возврат» и ответы на вопросы написаны как нейтральный шаблон. Цифры (стоимость, порог бесплатной
  доставки) берутся из `.env`, сроки доставки менеджер называет по телефону. Впишите свои условия.
- Реальные товары и фото через `/admin/products`. Демо-товары удалите. Без фото на сайте рисуется картинка-заглушка.
- Стоимость доставки и порог бесплатной доставки в `.env` (валюта уже гривна).

## Чего пока нет

- Онлайн-оплаты картой. Сейчас доступны «оплата при получении» и «перевод по реквизитам»; платёжный сервис
  (например LiqPay, WayForPay или эквайринг monobank) подключается отдельным шагом.
- Уведомлений о новых заказах и заявках по почте или в мессенджер — их видно только в админ-панели, заходите туда
  регулярно.
- Полноценной CRM (воронки, задачи, интеграции). Есть только раздел «Заявки» со статусами и заметками.
- Нескольких фото на товар и отзывов.

## Другие рынки

Сейчас один магазин работает в одной валюте (гривна) и на одном языке интерфейса (русский). Если позже понадобится
продавать в других странах, это отдельная доработка: цены в нескольких валютах, языки интерфейса, доставка и
оплата под каждую страну. Данные заказов при этом сохраняются.

## Устройство проекта

```
watch-shop/
  src/
    server.js, app.js, config.js, db.js, seed.js
    routes/    shop.js (витрина), cart.js (корзина и заказ), contacts.js (формы), admin.js (админка)
    lib/       products.js, orders.js, leads.js, phones.js, security.js, format.js, placeholder.js
    views/     EJS-шаблоны (admin/ — админка)
  public/      стили, скрипт, favicon
  scripts/     backup.js — резервная копия базы
  test/        автотесты (node:test)
  Dockerfile, docker-compose.yml, Caddyfile
```

Безопасность: параметризованные SQL-запросы, экранирование вывода, CSRF-токены во всех формах, подписанные
cookie корзины и входа, ограничение числа попыток входа и оформления заказов, строгий CSP без inline-скриптов,
проверка типа загружаемых фото по содержимому файла.
